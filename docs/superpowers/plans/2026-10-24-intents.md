# intents Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Rust terminal tool, `herdr-intents`, that captures intents as Markdown files in a group tree, refines them through a streaming conversation with a configurable agent CLI, and sends them to a new Herdr agent with the right handoff.

**Architecture:** One binary with modes `tui` (default), `add [--popup] [title]`, `--version`. Modules: `config` (intents.toml, templates, providers, handoffs), `store` (files, front matter, tree, moves, attachments, transcript), `provider` (argv templates + JSONL event parsing per CLI, proposal-block parser), `conversation` (subprocess streaming on a thread, cancel, resume ids), `editor` (hand-rolled text area), `send` (repo resolution, workbrokr prefix, Herdr calls), `ui` + `app` (ratatui panes and state machine). Shipped as its own Herdr plugin at `tools/intents/` in the `herdr-plugins` workspace.

**Tech Stack:** Rust 1.97 (2024 edition), `ratatui 0.30`, `crossterm 0.29`, `serde` + `toml 1`, `serde_yaml_ng 0.10` (front matter), `serde_json 1`, `slug 0.1`, `similar 3` (diff), `chrono 0.4`, `anyhow 1`, `shellexpand 3`, `nix 0.31` (signals). Dev: `insta 1`, `tempfile 3`. No `tui-textarea` (it targets ratatui 0.29); the text area is hand-rolled and small.

**Spec:** `docs/superpowers/specs/2026-10-24-intents-design.md` (same repo). Executors read it first; the toolbar design and code under `toolbar/` show the conventions to follow (lib + bin split, fake `herdr` script for tests, `herdr-plugin.toml` with `../target/release/` paths).

## Global Constraints

- Crate `herdr-intents` at `tools/intents/`, added to the workspace `members`. Plugin id `jefelabs.intents`, `min_herdr_version = "0.9.0"`, `platforms = ["macos", "linux"]`. Build commands reference `../../target/release/herdr-intents` (two levels up from `tools/intents/`).
- Data: `<root>/<group>/.../<slug>.md` with YAML front matter; attachments in `<slug>.assets/`; transcript in `<slug>.chat.md`. Root default `~/intents`. Groups are directories; `Inbox` is created on first run.
- Front matter fields exactly: `title, kind, state, created, updated, repo, tags, polished_at, sent_to, conversations`. States exactly `raw | refining | ready | sent`. Built-in kinds `issue | enhancement | idea`.
- Config dir: `INTENTS_CONFIG_DIR`, else `HERDR_PLUGIN_CONFIG_DIR` when `HERDR_PLUGIN_ID == "jefelabs.intents"`, else `~/.config/herdr/plugins/config/jefelabs.intents`. Templates under `<config>/templates/<kind>.md` and `<kind>.polish.md`, written from built-in defaults on first run, never overwritten.
- Providers built in: `agy` (default for polish), `claude`, `codex`, `copilot`; custom providers from config. The tool never passes any `--allow-all*`, `--dangerously-skip-permissions` or `--mode auto` style flag. Every provider runs in its JSON/JSONL print mode; reply text is read from events, never from a terminal dump.
- Reply contract: a fenced block ` ```proposal ` … ` ``` ` holding the full intent body, and a `questions:` list of `- ` lines. Without a proposal block, apply is disabled.
- `repo` is the main checkout: parent of `git rev-parse --git-common-dir` resolved from the current directory; never a worktree.
- Handoffs built in with `provider = "claude"`: `issue-report` (kinds `issue`), `enhancement-spec` (kinds `enhancement`), `grill` (`*`), `wayfinder` (`*`). workbrokr prefix only for the first two, only when `helmsmith.config.ts` exists at `repo` (overridable by config `workbrokr = true|false`).
- Send sequence: `herdr workspace create --cwd <repo> --label <title> --no-focus` → parse `.result.root_pane.pane_id` → `herdr agent start <name> --kind <provider> --pane <id>` → `herdr agent prompt <name> <prompt>`. Agent name = `intent-<slug-prefix>` matching `[a-z][a-z0-9_-]{0,31}`.
- Never `eprintln!` in the TUI path (panics on a dead pty); never `ratatui::restore()` directly: reuse the toolbar's pattern (events thread, static stop flag, error-ignoring restore, `process::exit`).
- Commit after every task; never commit `target/`.

## Review Focus

1. **Front matter the user hand-edited** (unknown field, missing `state`, `tags` as a string): the file still loads, unknown fields are preserved on save, missing fields take defaults. Task 2.
2. **Provider process that never ends or prints garbage** (no final event, non-JSON lines): the turn can be cancelled with `Esc`, the UI never blocks, garbage lines are shown as text rather than crashing the parser. Task 4.
3. **Reply without a proposal block, or a proposal block that is empty**: apply is disabled with a visible hint; nothing is written. Task 3 (parser) and Task 6 (UI state).
4. **Send when Herdr is absent or a Herdr call fails midway** (no `HERDR_BIN_PATH`; `workspace create` ok but `agent start` fails): the intent stays `ready`, the error names the failed step, and no `sent_to` is written. Task 7.
5. **Two toolbars (two workspaces) editing the same intent**: the second save detects a changed `updated` on disk and asks before overwriting instead of clobbering. Task 2 (conflict check) and Task 6 (prompt).
